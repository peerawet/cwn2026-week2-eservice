# QUESTIONS-TO-TA · จุดที่โจทย์/การ์ด TC กำกวมและเจอจริงระหว่างรัน

ตามพรอมต์ขั้น 4: ถ้า "แผนผิด" ห้ามแก้เอง ให้จดเป็นคำถามถึง TA · ข้อ 1–5 เจอจากการรันจริง (ดู `app/tests/runs/`) · ข้อ 6–8 เป็นจุดกำกวมที่ผู้เขียนเทสต์พบตอนอ่านการ์ด TC (ยังไม่เคยทำให้เทสต์ล้ม)

|---|---|---|---|---|
| 1 | TC-WORKFLOW-05 · TC-PDPA-03 | การ์ดระบุข้อความของ `return-reason-error` / `unmask-error` เมื่อเกิด error แต่ **ไม่ได้ระบุว่าก่อนเกิด error element ต้องไม่ถูก render (count=0) หรือเป็นแค่ซ่อน** เว็บ (ส่วน workflow) render `<p hidden>` ว่างไว้ตลอด ส่วนส่วน citizen สร้าง element ตอนเกิด error | เทสต์ตรวจเงื่อนไขเริ่มต้นแค่ "ไม่มีข้อความ error ที่มองเห็น" (`not.toBeVisible`) ไม่ใช่ count=0 | element error ที่ไม่มี error ต้อง "ไม่มีใน DOM" หรือ "ซ่อนได้"? ถ้าต้องไม่มีใน DOM เว็บส่วน workflow ต้องแก้ |
| 2 | TC-DASH-03 · TC-AUDIT-01 · TC-RBAC-05 | การ์ดบอกให้ "ดาวน์โหลดไฟล์" แต่ลิงก์ `<a download>` ถูกเบราว์เซอร์จัดการก่อนชั้นเครือข่าย Playwright (route / response / CDP ไม่เห็นคำขอ) จึงอ่าน **Content-Type** ของไฟล์ที่ดาวน์โหลดโดยไม่ยิงคำขอซ้ำไม่ได้ ส่วนคำขอซ้ำจะเพิ่มแถว Audit `EXPORT` | รับไฟล์จากเหตุการณ์ `download` และตรวจ `Content-Type: application/pdf` ด้วยคำขอตรงหลังนับ Audit แล้ว (DASH-03 ขั้นท้าย) | ยืนยันว่าตรวจ Content-Type ด้วยคำขอแยกได้ และจำนวน `EXPORT` ในการ์ดนับเฉพาะการกดปุ่ม |

| 4 | (CONTRACT §0 ข้อ 5, NFR-03) | PDF ที่สร้างใส่วันที่สร้างไฟล์จาก **เวลาเครื่องจริง** ไม่ใช่นาฬิกาทดสอบ (`2026-12-01T09:00`) ไม่ผิดตามตัวอักษร (กฎนาฬิกากำหนดกับ "กฎธุรกิจ") แต่ผลของไฟล์จึงไม่ซ้ำกันเป๊ะระหว่างรอบ | ไม่แก้ | ต้องการให้ metadata ของเอกสารอ่านจากนาฬิกาทดสอบด้วยหรือไม่ |
